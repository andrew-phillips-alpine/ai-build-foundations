# Adoption Playbook

A tool only counts once people use it without being asked. This is how a new build becomes a habit.

## Before launch

- Build on the team's own work, not a demo dataset.
- Agree who owns the tool day to day.
- Write a one-page SOP: what it does, when to use it, when not to, and who to ask. Use `templates/sop.md`.

## Launch

- Run short sessions on the team's live work, not a slide deck.
- Show one task done the old way and the new way, side by side.
- Keep the first version narrow, so it works every time.

## After launch

- Hold office hours for the first few weeks.
- Offer one-to-one coaching for the people who will use it most.
- Track usage weekly against the success measure in the build brief.
- Collect the cases where people went back to the old way, and fix the cause.

## Review

- At 30 days, compare the result with the baseline.
- Expand the tools that earned it.
- Cut the ones nobody uses, and record why.

## What to teach

Most of it is judgement, not technology:

- When to use AI and when not to.
- How to check an output before relying on it.
- How to tell whether it worked.
